## 项目规则

- 任意代码修改前，阅读本文件和 `docs/dev_spec.md`。
- 优先遵循用户最新明确指令；安全、权限、测试、提交规则不可绕过。
- 禁止提交 `.env`、密钥、令牌、本地数据库、调试输出和临时文件。
- 未经用户明确授权，不执行生产写操作、真实支付、发券、删除数据、发布或部署。
- 普通 feature 分支推送：`<允许 / 需确认>`。
- 受保护分支、force push、发布和部署必须经明确授权。

## 开发流程

- 项目范围、阶段、验收、关键决策和当前状态以 `docs/dev_spec.md` 为准。
- L2/L3 开发或阶段恢复时，使用 `$spec-driving`。
- 当前环境存在专项 Skill 时，按任务选择需求澄清、计划、调试、测试、验证或收尾方法。
- L2/L3 进入执行前，先在 dev spec 判定阶段形态；存在关键不确定性时默认证据优先。
- worktree、完整 `writing-plans`、子代理并行、完整 TDD 套件仅在阶段形态为“实现优先”且推进条件满足后自动选用；证据优先阶段如确有必要，记录原因后按需使用。
- 验收不接受仅 HTTP 200、仅代码审查或仅 mock 数据；必须按 dev spec 的真实验证标准提供证据。
